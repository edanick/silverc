Final-phase checks (NOT run in the no-launch phase):
1. Build+run with the self-host compiler (string_helpers.srp):
   program output must match the one line above byte-for-byte. This
   is a mirror fixture (it re-implements the fixed std/string.sr
   kernels — the parts+one-join pad/padLeft/padRight/slugify, the
   hoisted-length equals loop and the floored-start projectFind —
   in user code, following the token_node_defaults pattern) and
   cross-checks the pad/slugify calls against the builtin methods.
2. Byte-identity: compile the same programs with HEAD and with the
   fix and diff the outputs — every case in main.sr must be
   identical (pad with count 0 / negative count / empty fill /
   multi-char fill using only the first char; slugify with leading
   and trailing separators, doubled separators, punctuation, an
   empty input and a separators-only input; equals with equal and
   unequal lengths case-insensitively; projectFind with a negative
   start, which the old code read out of bounds).
3. Negative (future-regression proof): mutate any mirrored kernel
   in a scratch copy of main.sr (e.g. return a per-character +=
   builder, or drop the first=0 floor) — the fixture must fail
   with exit code 1, and the EXPECT.txt byte-identity half must
   still hold for the unmutated kernels.
4. Measurement: on a scratch bench (a 10 KB pad count and a
   10 KB slugify input), pre-fix peak RSS must be ~quadratic in
   the built length; post-fix it must be linear (one join per
   result). Compare /usr/bin/time -v before/after on the same
   fixture.
