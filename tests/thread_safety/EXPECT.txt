1. Build+run with the self-host compiler (thread_safety.srp):
   program output must match the one line above byte-for-byte. This is
   a mirror fixture (it re-implements the guarded arithmetic kernels of
   compiler/resource.sr and compiler/thread_safety.sr in user code
   rather than importing the compiler modules, following the
   resource_adaptive / cli_flags_holder pattern), so it runs
   identically on every host.
2. Byte-identity: registry admission affects when work runs, never what
   is produced (TS-9). The same input compiles to a byte-identical
   binary with one thread, total-2 threads, and any --threads count.
3. Negative (future-regression proof): mutate any kernel in main.sr
   (e.g. safetyMargin max(2, total/4) to 2 flat, or dropping the +1
   demand overhead, or chunkSize dividing by default instead of the
   actual worker count) — the fixture must fail with exit code 1. That
   is the property a future edit breaking compiler/resource.sr or
   compiler/thread_safety.sr would violate.
4. Registry fallback: with the registry dir removed or unwritable the
   compiler must still compile, printing the "running alone" warning
   (Rule 12), never hanging (Rule 11) and never exiting with an error
   the user did not cause.
