visibility sibling-std + shared-text fixture (MEMORY.md §3.2 rank 4/5, INV-15)

Run in the final phase with the self-host compiler (standalone mode).
Files are NOT run in the no-launch phase.

  1. Positive (must compile + run, exit 0, prints vis-sibling-ok):
       silverc main.sr -o out.exe && ./out.exe
     helper resolves via the sibling-std trio (<sib>/std/helper.sr),
     mod_a via the plain sibling. Both are collected by the driver and
     reused (not re-read) by the checker.

  2. Negative (must FAIL with the VisibilityChecker diagnostic, exit 1):
       silverc main_internal.sr -o out.exe
     Expected diagnostic (file name may differ by platform path):
       `[main_internal.sr]` ... `secretH` is internal to project `helper`
       and cannot be used here, at line ..., column ...
     The SAME diagnostic text must appear before and after the change.
     Before the ladder unification the checker did not probe the
     sibling-std trio, so this case saw a different winner than the
     compiler; after it, both see std/helper.sr.

Memory check: pad the chain before measuring. Deepen the import chain
(main -> helper -> mod_a chain with large dummy modules ~1 MB of comment
text each) and measure peak RSS with /usr/bin/time -v before and after
on the same padded tree. The shared-text handoff removes one full read of
every external module (checker probe text rides from DrvModuleCache), so
peak RSS after the fix should drop by ~one copy of the external sources
plus the duplicate probe reads. Semantics must stay byte-identical: same
program output, same diagnostics.
